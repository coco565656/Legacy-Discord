# Snow Leopard compatibility boundary

## Supported range

- Minimum: Mac OS X 10.6.8 Snow Leopard, x86_64
- Formal range: 10.6.8 through OS X 10.8.5 Mountain Lion
- Best effort: OS X 10.9.5 Mavericks
- Development preview only: current macOS with DevLocal or login-preview

Production Debug and Release use `ARCHS = x86_64` and
`MACOSX_DEPLOYMENT_TARGET = 10.6`. DevLocal remains a separate current-SDK
configuration and must not be used as evidence of legacy compatibility.

## Compatibility changes

- `DLCompatibilityPopover` uses native `NSPopover` when the class exists on
  Lion or later. Snow Leopard receives a small AppKit `NSPanel` with the same
  content view controller and close callback.
- Split-view holding priority is invoked only after a runtime selector check;
  Snow Leopard uses the existing split-view sizing code without that hint.
- Session storage uses the generic-password `SecKeychain` functions available
  before Lion rather than the Lion-only `SecItem` dictionary API. The service
  and account names are unchanged so existing items remain addressable.
- The source verifier parses against a 10.6 deployment target.

These are narrow compatibility adaptations. Message views, layout, themes,
Markdown, fixture replay, and live rendering continue to share the same paths.

## Required legacy verification

The Phase 1C checkpoint was compiled and partially exercised on a connected
Mac OS X 10.6.8 machine. This is real Snow Leopard evidence, but it is not the
complete formal matrix. Test the same x86_64 artifact on every formal target
before declaring compatibility complete.

1. Build with a legacy SDK and confirm an executable minimum version of 10.6.
2. Launch on 10.6.8, 10.7.5, and 10.8.5.
3. Log in, quit, restore the Keychain session, then log out and verify deletion.
4. Load the bundled curl, OpenSSL, and crypto libraries and complete a TLS
   connection on Snow Leopard.
5. Open and close profile, emoji, and sticker UI. Confirm the Snow Leopard
   panel fallback and the native Lion-or-later popover paths separately.
6. Exercise messages, attachments, images, reactions, search, threads,
   profiles, settings, themes, scaling, reconnect, and clean termination.
7. Repeat the smoke test on Mavericks where practical.

The Phase 1C application launched with the bundled x86_64 curl/OpenSSL/crypto
libraries on 10.6.8. An authenticated TLS request remains unverified; loading
the libraries alone is not a network-compatibility result.

## Toolchain and fallback

The Phase 1C source compiled and linked on Snow Leopard with Xcode 3.2.6,
LLVM Clang 1.0, the Mac OS X 10.6 SDK, `ARCHS=x86_64`, and deployment target
10.6. The first cross-version production candidate remains Xcode 4.6.3 with
the OS X 10.8 SDK; Xcode 5.0.2 remains a secondary Mountain Lion check.

Xcode 3.2.6 cannot compile the current XIB documents directly. The Snow build
therefore excludes XIB compilation and combines the Snow-built binary and
Info.plist with the last verified Snow-compatible compiled nibs. The XIBs were
unchanged during Phase 1C. Do not use nibs generated by current Xcode 26 on
Snow Leopard: its `NIBArchive` format raises `NSInvalidArgumentException`
inside `NSKeyedUnarchiver` before application launch. Preserve a known-good
compiled-nib fallback whenever changing the build process, and regenerate the
legacy nibs with a compatible Interface Builder whenever an XIB itself changes.

The 2026-09-09 Phase 1C checkpoint is stored on both machines at:

`~/Desktop/LegacyDiscord-Phase1C-2026-09-09`

It includes separate fixture and login applications, source, build products,
screenshots, logs, and the intentionally retained failed modern-nib launch
evidence. Earlier Phase 1B Desktop checkpoints were not overwritten.

Xcode 26 can compile the production sources with target 10.6, but its final
link fails because that Xcode no longer ships the Objective-C backwards-
compatibility `libarclite` archive. `CLANG_LINK_OBJC_RUNTIME` remains enabled
for production because it is the supported way to supply older systems with
runtime support for newer Objective-C language features. The current-Mac login
preview therefore keeps its isolated 10.13 override; the formal 10.6 artifact
must be produced with the legacy toolchain.

No compatibility change is committed automatically. Until the legacy smoke
test is accepted, the beta1 baseline and every local compatibility edit remain
visible as ordinary Git history and working-tree differences. Do not discard
unrelated local development changes when reviewing or reverting this phase.
